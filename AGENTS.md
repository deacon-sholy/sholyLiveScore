# Repo notes for AI coding sessions

## Verification & health
- Build: `npm run build` (Vite build + `scripts/prerender.mjs`). Typecheck: `npm run typecheck`. Lint: `npm run lint`. Tests: `npm run test` (Vitest). Run all four before finishing any change.
- Vitest is pinned to `^2.1.9` for Vite 5 compatibility (v5 needs Vite 6+). Keep tests out of `netlify/functions/` — Netlify treats every file there as a deployable function and rejects dots in function names; tests live in `tests/`.
- Commit message style: lowercase imperative, e.g. `feat: premier league first in stable league order; add saudi pro league, indian super league`.
- Uncommitted work should always end a session committed + pushed (`git push`) and, if the site should be live, manually deployed.

## Deploy
- Manual (CI is a no-op until GitHub secrets are set — see README "Operator checklist"):
  `netlify deploy --dir=dist --functions=netlify/functions --prod --site ecbf0521-f10a-499b-9cb9-d2975fd3616d --no-build` (run `npm run build` first; always pass `--no-build`).
- Verifying the live site: use `curl.exe -4` — Windows curl prefers IPv6 and returns HTTP 000 otherwise.
- Netlify function execution ≈10s limit. A slow ESPN summary (occasionally ~9s+) can kill a `?league&event` detail request with HTTP 000. Retry once / try another live match; normal latency is ~2–3s. Nothing to fix on our side.

## Data source (ESPN)
- Scores: `https://site.web.api.espn.com/apis/site/v2/sports/soccer/{slug}/scoreboard?...`
- News: `https://site.api.espn.com/apis/site/v2/sports/soccer/{slug}/news?limit=N` (use `all` for global soccer). Articles expose `headline`, `description`, `published`, `byline`, `images[type=header].url`, `links.web.href`, `categories[]` (league tags) and `type` (`Story`/`HeadlineNews`/`Recap` are readable; skip `Media`/video).
- Summaries (events, stats, form, h2h): `https://site.web.api.espn.com/apis/site/v2/sports/soccer/{slug}/summary?event={id}`
  - `boxscore.teams[].statistics[]` keys: `possessionPct`, `totalShots`, `shotsOnTarget`, `wonCorners`, `foulsCommitted`, `yellowCards`, `redCards`, `offsides`, `saves`, `accuratePasses`, `totalPasses`, `passPct` (0–1 scale).
  - `lastFiveGames[].events[]`: `gameResult` (W/D/L), `opponent`, `score`, `atVs`, `gameDate`. `opponent` is **not always a string** — some competitions send a team object with `displayName`/`abbreviation`; `extractForm` must normalise it to a name or React throws "Objects are not valid as a React child" on the Form tab.
  - `seasonseries[]`: `title`/`summary` for H2H; `events[]` (past meetings: date, competitors w/ scores, `statusType.shortDetail`, `competitionName`) feeds the "Head-to-head" card, max 10 newest.
  - `summary.rosters[]` holds the real lineup once a match is live/finished: `formation` (e.g. `4-2-3-1`) and `roster[]` entries with `starter`, `jersey`, `position`, `formationPlace`, `subbedIn/Out` and player `stats` (`totalGoals`, `goalAssists`, `yellowCards`, `redCards`, `saves`). Pre-match rosters contain a single placeholder with no formation — `extractLineups` requires ≥7 starters per side and returns null otherwise. `formationPlace` is a generic 1–11 slot index (not formation-shaped), so the UI groups starters by position instead of drawing a pitch.
  - `summary.keyEvents` is the event source of truth. `header.competitions[0].details` is trimmed to ~2 nameless rows for some tournament finals (e.g. the World Cup final exposes 8 events in the scoreboard but only 2 in the summary header). `keyEvents` has full names/assists; use `details` only when `keyEvents` is missing.
  - `keyEvents` shapes events differently per competition: most use `athletesInvolved[]`; friendlies rely on `team.id`. `mapEvent` handles both and falls back to home/away team ids.
  - `substitution` events list the incoming player first, so the second participant is who comes **off** (`Off: X`).
- League slugs: PL `eng.1`; Champions League `uefa.champions`, Europa `uefa.europa`, Conference `uefa.europa.conf`; Spain `esp.1`, Italy `ita.1`, Germany `ger.1`, France `fra.1`, Turkey `tur.1`, Netherlands `ned.1`, Portugal `por.1`, USA `usa.1`, Saudi `ksa.1` (NOT `sau.1` — that 400s), India `ind.1`. Africa: Nigeria `nga.1`, South Africa `rsa.1`/`rsa.2`, Ghana `gha.1`, Kenya `ken.1`, Zambia `zam.1`, Uganda `uga.1`, Zimbabwe `zim.1`, CAF `caf.champions`/`caf.confed`/`caf.nations`. Egypt/Morocco/Algeria/Tunisia and most other African codes 400 in the core API — don't add them. `qat.1`/`uae.1` don't exist in the scoreboard API. `eng.1` and `rus.1` both display "Premier League" (name collision). Women's slugs: `eng.w.1`.
- International slugs: `fifa.world`, `fifa.friendly`, `uefa.nations`, `uefa.euro`, `fifa.cwc`, `fifa.worldq.uefa`, `fifa.worldq.conmebol`, `fifa.worldq.concacaf`, `fifa.worldq.afc`, `fifa.worldq.caf`.
- International team logos: national teams expose `team.logos[0].href` rather than `team.logo`; read both.
- Scraped/blocked: league top-scorers endpoints return 404/400 for soccer — do not pursue.

## Architecture shortcuts
- `src/lib/leagues.ts` is the single source of truth for the league list (order, grouping, `standings` support, `seoName` disambiguation). Client and both functions import it; there is no `netlify/functions/leagues.ts` and no `LEAGUE_META` copy in `seo.ts`. Functions reach it via `../../src/lib/leagues`, so Netlify's bundler must follow cross-directory relative imports.
- `?league&event` on the function now returns a fully built `match` plus `events`/`stats`/`form`/`h2h` from the summary, so `MatchPage` needs only one request and works for any past date.
- `?league&event&live=1` returns just `{ match }` from the league scoreboard (4s cache). `MatchPage` polls it every 5s while the match is live/halftime for fast goal/score updates, while the full summary poll stays at 10s for stats/form/h2h.
- Single league fetch: `?league=<slug>[&date=YYYY-MM-DD]` returns that league's scoreboard only (used by `/league/:slug`).
- Standings: `?standings=<slug>` returns `groups[]` so World Cup/Euro show per-group tables; domestic leagues return a single implicit group. `standings: false` entries (friendlies) have no table.
- The all-leagues fan-out is capped at 8s with a shared deadline, per-request timeouts derived from remaining time, and 1 attempt when <3s remain. Unfinished leagues fall back to stale cache. Keep total runtime under Netlify's ~10s limit.
- News: `netlify/functions/news.ts` fans out over several ESPN news feeds (`all`, EPL, UCL, Nigeria, South Africa, CAF), dedupes by id/headline, filters to readable article types and caches 2min. `?id=<espn-id>` fetches `now.core.api.espn.com/v1/sports/news/{id}`, converts the HTML `story` to plain text blocks (never renders raw HTML) and caches 10min. `src/pages/NewsPage.tsx` at `/news` auto-refreshes every 60s and filters by league tag; cards open local `/news/:id` pages (`NewsArticlePage.tsx`), so readers stay on-site. The home page puts the latest stories in a desktop-only right-hand sidebar (`src/components/HomeNews.tsx`, 1 lead + 4 rows); it is hidden below the `lg` breakpoint and no feed request is made there.
- Routes (react-router-dom): `/` home, `/news`, `/news/:id`, `/league/:slug`, `/league/:slug/match/:id`, `/download`. Every page sets title/description/canonical (+ JSON-LD via `src/lib/seo.ts`). `src/pages/` = HomePage, LeaguePage, MatchPage, NewsPage, NewsArticlePage, DownloadPage; shared chrome is `SiteHeader` + App shell.
- Sitemap: `netlify/functions/sitemap.ts` (redirect from `/sitemap.xml` in netlify.toml; league URLs come from `src/lib/leagues.ts`). No `<lastmod>` — ESPN gives no update timestamp and guessing it hurts SEO.
- Favorites are client-side only: `src/lib/useFavorites.ts`, localStorage key `sholy-favorite-leagues`; the "favorites" filter fetches `all` then filters in the client.
- Personalization is all client-side localStorage: `useFollowedTeams` (`sholy-favorite-teams`, powers the "My Teams" filter and goal alerts), `useSavedArticles` (`sholy-saved-articles`, news bookmarks + "Saved" tab), install-prompt dismissal (`sholy-install-dismissed`), and goal-alert opt-in (`sholy-goal-alerts`). `useGoalAlerts` only fires when the tab is hidden and a followed team's score actually increases; the baseline is set on first render so enabling mid-match never fires retroactively. Goal notifications go through the SW (`public/sw.js` handles `notificationclick` by focusing/opening the match URL).
- Calendar export: `src/lib/calendar.ts` builds a 2-hour `.ics` with a match deep link; only shown for scheduled matches.
- Standings seasons: the modal offers the last 11 seasons via `?standings=<slug>&season=YYYY` (validated in the function).
- Durable cache: `netlify/functions/livescore.ts` layers Netlify Blobs (`@netlify/blobs`, store `sholy-scores-cache`) behind the in-memory cache; it silently no-ops outside Netlify. Keep total function time under the ~10s limit.
- Analytics: `src/lib/analytics.ts` injects gtag only when `VITE_GA_ID` is set; no-op otherwise.
- Android: `npm run apk` runs `scripts/build-apk.ps1` (gradle `assembleRelease` + publish) and refreshes `public/downloads/sholy-scores-<version>.apk` plus the `SholyScores-<version>.apk` root copy. `APP_VERSION` in `src/lib/appInfo.ts` must match `versionName` in `android/app/build.gradle` — the `/download` link is built from it. `android/keystore.properties` and `android/sholy-release.keystore` are gitignored (never commit the key); `public/.well-known/assetlinks.json` must carry that keystore's SHA-256 or App Links verification fails (harmless — links then just open in the browser).
- Netlify: static files win over the `/*` → `/index.html` rewrite (shadowing), so `/downloads/*.apk` and `/.well-known/assetlinks.json` are served as files. `/sitemap.xml` is rewritten to a function. `scripts/prerender.mjs` emits flat shells (`news.html`, `download.html`, `league/<slug>.html`) and `netlify.toml` rewrites the clean URLs to them (status 200) — target flat files, not `<dir>/index.html`, or Netlify's pretty-URL 301 adds a trailing slash and breaks the canonical tags.
- Smoke test pages with headless Edge: `npm run preview`, then `msedge.exe --headless=new --dump-dom http://localhost:4173/<route>` (vite preview binds `::1`).
